# Browser-only CTC replacement provenance

## Finding

No simpler option proves CTC ownership through current firefox-cli surfaces. This source review did not test live Firefox.

## Options

- **Placeholder and landing page:** CTC could create the correct-container destination at a temporary extension page with a one-use URL token, while it keeps the source open for polling. firefox-cli exposes URL and container metadata ([schema](https://github.com/respawn-llc/firefox-cli/blob/c118396bcd36698a395773724663cc1f1493a04a/packages/protocol/src/target.ts#L3-L15)). But Firefox's `moz-extension://<UUID>/…` host is an internal UUID, not CTC's stable Gecko ID `ctc@kau.sh); current CLI has no trusted mapping ([MDN runtime.getURL](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/runtime/getURL), [Extension Workshop](https://extensionworkshop.com/documentation/develop/testing-persistent-and-restart-features/), [CTC manifest](https://github.com/kaushikgopal/ff-container-traffic-control/blob/5c4227ce08dd9a1c58f000da5d190b8c0baef0a2/manifest.json#L40-L46)). A nonce correlates but does not authenticate. Auto-redirect races polling. `tab.new` can return a landing-tab ID, but its handler re-resolves that ID after creation; CTC may already remove it during target navigation ([CLI handler](https://github.com/respawn-llc/firefox-cli/blob/c118396bcd36698a395773724663cc1f1493a04a/packages/extension/src/browser-handlers/tabs-windows.ts#L22-L35), [CTC replacement](https://github.com/kaushikgopal/ff-container-traffic-control/blob/5c4227ce08dd9a1c58f000da5d190b8c0baef0a2/src/background.js#L274-L291)). Any background-held receipt state must survive suspension; use URL state or `storage.session`, not memory alone ([MDN storage.session](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/session)).
- **Opener and delayed removal:** Firefox permits `openerTabId` only in the same window and reports it only while the opener exists there ([tabs.create](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/create), [tabs.Tab](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/Tab)). Retention gives a hint, not proof. The CLI schema omits opener; page-created tabs can share it. Timed retention races polling.
- **Title, window, group:** Window ID and title do not prove creator. Firefox supports groups from 138, but CTC lacks `tabGroups` permission and firefox-cli omits `groupId` ([Firefox 138](https://developer.mozilla.org/en-US/Firefox/Releases/138), [CTC manifest](https://github.com/kaushikgopal/ff-container-traffic-control/blob/5c4227ce08dd9a1c58f000da5d190b8c0baef0a2/manifest.json#L13-L24), [CLI schema](https://github.com/respawn-llc/firefox-cli/blob/c118396bcd36698a395773724663cc1f1493a04a/packages/protocol/src/target.ts#L3-L15)). Groups remain mutable metadata.
- **Page eval:** firefox-cli runs eval in the page's MAIN world ([adapter](https://github.com/respawn-llc/firefox-cli/blob/c118396bcd36698a395773724663cc1f1493a04a/packages/extension/src/background-browser-adapter.ts#L223-L229)); page code lacks extension runtime authority. Firefox blocks injection into extension pages ([MDN scripting.executeScript](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/scripting/executeScript)). DOM receipts and page events are spoofable. A signed nonce receipt needs a CTC content-script/background bridge, wrapper-trusted verification key, and tab, URL, container, expiry, and replay checks. That is not simpler.
- **IDs:** Firefox tab IDs are unique only within one browser session ([tabs.Tab](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/Tab)). Bind receipts to fresh tab state and expiry.

## Recommendation

Keep a CTC receipt bridge if proof is required. Treat placeholders, opener links, titles, groups, and tab scans as heuristics unless the wrapper authenticates CTC's origin. No live timing claim is verified.
